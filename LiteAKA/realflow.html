LiteAKA · 第 6 页 · 实机版

Flow：App → SIM → App → 服务器 → Open5GS

一共五个角色：

  • SIM：手机里的真卡。K 和 OPc 只在卡里，永远不出来。
  • LiteAKA App：手机上的 App（com.zecheng.liteaka），用 root 拿到的权限直接给 SIM 发 APDU。
  • LiteAKA 服务器：桌面上的 liteaka_server.py，端口 8780。只转发，不算任何密码学的东西。
  • Open5GS：AUSF、UDM、UDR，出题和判分都在这里。
  • 其他 App：比如 Demo Client，只来问一句"认证过没有"。

这是双向认证：SIM 在 S3 检查 AUTN 里的 MAC，确认出题的是自己的网络； AUSF 在 N2 比较 RES* 和 XRES*，确认卡是真的。两边都通过才算成功。

0. 事先配好的东西

在哪东西怎么来的
SIMIMSI、K、OPc、SQNMS卡出厂时写进去的。K、OPc 读不出来；SQNMS 是卡自己记的"见过的最大 SQN"
Open5GS（MongoDB）IMSI、K、OPc、AMF = 8000、SQN登记：在桌面上运行 subscribers.py add <imsi> <ki> <opc>（K、OPc 抄自卡的说明书）。新登记的 SQN 从 0 开始
服务器MCC = 999、MNC = 70、AUSF 地址写在代码里
App服务器地址、卡槽号界面上填，默认 http://10.168.1.39:8780

2. SQN 不同步时：重同步

新登记的 SIM、或者数据库被改过，数据库里的 SQN 就可能比卡里记的小。这时卡在 S4 拒绝，返回 AUTS：

 SIM                  LiteAKA App                    LiteAKA 服务器              Open5GS
  │──── DC AUTS ──────────►│                               │                              │
  │                        │ R1. POST /liteaka/v1/resync   │                              │
  │                        │   {session, auts}             │                              │
  │                        │──────────────────────────────►│ R2. 用旧 session 里的 RAND   │
  │                        │                               │ POST ue-authentications      │
  │                        │                               │   + resynchronizationInfo    │
  │                        │                               │   {rand, auts}               │
  │                        │                               │─────────────────────────────►│ R3. UDM: ogs_auc_sqn
  │                        │                               │                              │     解出 SQN_MS，校验 MAC-S
  │                        │                               │                              │     SQN = SQN_MS + 33，写回 UDR
  │                        │                               │                              │     重新出题（同 N1）
  │                        │◄── 新的 {session, rand, autn …}─────────────────────────────│
  │                        │ R4. 回到 A4，用新 challenge 再做一次（最多重同步一次）       │

3. 每一步在做什么

App（A1–A10）

步做什么为什么
A2–A3开一个逻辑通道读 IMSI，读完关掉读 IMSI 要切到 DF_GSM 目录，切过去以后这个通道就不在 USIM 应用里了，在同一个通道上做认证会得到 6985
A4–A5开一个新的逻辑通道做认证同上
A6RES* = HMAC-SHA-256(CK‖IK, 0x6B ‖ SN name ‖ RAND ‖ RES) 的低 128 位TS 33.501 Annex A.4。CK、IK 只用在这一步
A7CK、IK 清零LiteAKA 不派生任何加密 / 完整性密钥
A8本地算 HRES*，和服务器给的 hxresStar 比只是自检，不影响结果；真正判分在 AUSF
A9成功：存 SUPI、认证时间、过期时间（认证后 24 小时）；失败：清掉。过期后状态自动变成"未认证"，App 上显示 EXPIRED失败时清掉，避免留着上一次的成功状态
A10ContentProvider 回答其他 App只回答 yes / no 和 SUPI，不回答任何密钥

SIM（S1–S5）

步做什么失败时返回
S1AK = f5(K, RAND)，SQN = AUTN 前 6 字节 ⊕ AK—
S2–S3XMAC = f1(K, RAND, SQN, AMF)，和 AUTN 里的 MAC 比98 62：出题的人没有这张卡的 K
S4SQN 必须比卡里记的新DC + 14 字节 AUTS = (SQNMS ⊕ AK*) ‖ MAC-S
S5RES = f2，CK = f3，IK = f4，更新 SQNMS成功：DB ‖ RES ‖ CK ‖ IK

服务器（V1–V5）

步做什么
V2SUCI = suci-0-999-70-0000-0-0-<MSIN>（null scheme，不加密）；SN name = 5G:mnc070.mcc999.3gppnetwork.org
V3随机生成一个 session id，记下 IMSI、RAND、AUSF 给的确认链接、时间。120 秒过期
V4session 只能用一次，取出来就删掉
V5AUSF 回的 kseaf 不往下传，直接丢掉

Open5GS（N1–N3）

函数级的细节见 第 5 页。要点是：出题（N1）要经过 AUSF → UDM → UDR 三个网元；判分（N2）只在 AUSF 里比较一次； N3 里的 auth-events 和 KSEAF 对 LiteAKA 没有用。
