第三步 · 每个 K 留不留

全部 K 的派生树（按时间从上往下）

  • ① 开卡时预置：K 和 OPc 写进卡和 UDR。
  • ② 每次认证时：K 和 RAND 进 f1–f5，得到 MAC-A、RES、CK、IK、AK；SQN 不同步时卡再用 f1*、f5* 算 MAC-S 和 AK*。这一层就是初始认证本身，除了可选的 f5**，全部保留。
  • ③ 认证成功以后：从 CK‖IK 派生 KAUSF，再往下分三支：KSEAF → KAMF → NAS / 空口 / 切换 / 非 3GPP / 4G 互通的密钥（加密那条链）；SoR / UPU 的 MAC（运营商下发配置）；AKMA（给别的应用）。LiteAKA 只留 AKMA 这一支。
  • 红色里还没定的：KN3IWF 等非 3GPP 接入密钥、K'ASME（4G 互通），先按 AI 建议标红，到第 6、7 组再定。

5G AKA 和 LiteAKA：子集和边界

5G AKA 跑一次，做的不只是认证：它同时完成认证、密钥协商，并为之后的通信建立保护。LiteAKA 只取认证这一块，所以它是 5G AKA 的子集。 下面按功能分三类：绿色 = LiteAKA 保留（子集），黄色 = 在边界上（只留一部分，或暂时不考虑），红色 = 不要。

  • 双向认证：网络用 RES* / XRES* 确认卡是真的；卡用 AUTN 里的 MAC-A 确认网络是真的。
  • 防重放：SQN 保证每道题只能用一次；卡和网络的 SQN 对不上时，用 AUTS 重同步。
  • 隐藏 SQN：AK、AK* 把来回传的 SQN 盖住，别人没法靠 SQN 追踪同一张卡。
  • 绑定服务网络：RES* 的输入里带着服务网络的名字，认证结果只对这个网络有效。
  • KAUSF：保留，但只留给 AKMA；它的另外两个用途（往下派生 KSEAF、SoR / UPU）不要。
  • CK、IK：保留，但只当算 RES* 的中间值，不再像 3G 那样直接加密；卡里会一直存到下一次认证。
  • 给别的应用复用认证结果（AKMA）：方向已经定了，具体留到哪一层暂时不考虑。
  • EAP-AKA'：卡里跑的是同一个 AKA，只是换了一种封装，暂时不考虑。
  • 身份隐私（SUCI / 5G-GUTI）：和认证本身无关，但不做就要明文发 IMSI，暂时不考虑。
  • 密钥协商：KSEAF → KAMF 往下的整套密钥层级。
  • 后续通信保护：NAS、RRC、用户面的加密和完整性保护，以及开启它们的 Security Mode Command。
  • 移动时的密钥延续：切换（NH、KNG-RAN*）、换 AMF（K'AMF）、从 RRC_INACTIVE 恢复。
  • 归属网络下发配置的保护：SoR、UPU。
  • 和 4G、非 3GPP 接入（如 Wi-Fi）互通时的密钥。

边界上最要紧的一点：在 5G 里，"认证之后的每条消息都来自认证过的那一方"，是靠红色那部分逐条保护来保证的。 LiteAKA 去掉了它们，换成认证成功后留下的一个认证状态，让后续功能来查；这个状态本身不对每条消息做密码学验证。 认证状态是 LiteAKA 在 5G AKA 之外加的一层，不属于 5G AKA 本身。
