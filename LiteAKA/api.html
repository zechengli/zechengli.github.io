所有 API

Verifier 只提供两个接口：POST /start 和 POST /finish。 传输格式为 HTTP + JSON，所有二进制字段都用小写 hex。

Client 端还有两个本地判定结果（mac_fail、sqn_fail），它们不经过网络。

① POST /start

申请一个 challenge。对应 Flow 里的 A1–A8。

请求

POST /start
Content-Type: application/json

{ "supi": "imsi-001010123456789" }
字段类型必填说明
supistring是用户标识，Verifier 里必须事先配好

成功：200

{
  "rand": "23553cbe9637a89d218ae64dae47bf35",
  "autn": "55f328b43577b9b94a9ffac354dfafb3"
}
字段长度内容
rand16 字节 = 32 hex随机数 RAND
autn16 字节 = 32 hex(SQN⊕AK)[6] ‖ AMF[2] ‖ MAC[8]

示例值取自 3GPP TS 35.208 测试集 1（那里 AMF = b9b9，不是 LiteAKA 的 8000），只用来说明格式。实际每次都不一样。

失败

HTTPreason什么时候
404unknown_supiVerifier 里没有这个 SUPI
400bad_requestbody 不是 JSON，或者缺少 supi
{ "ok": false, "reason": "unknown_supi" }

副作用

  • 这个 SUPI 的 SQN 加 1（即使之后认证失败也不回退）。
  • 写入 pending，并覆盖该 SUPI 之前的 pending。

② POST /finish

提交 RES*。对应 Flow 里的 C1–C5。

请求

POST /finish
Content-Type: application/json

{
  "supi": "imsi-001010123456789",
  "res_star": "b0e35b23dbd7a18c848bfad91135e3fd"
}
字段类型必填说明
supistring是和 /start 时相同
res_star32 hex是Client 在 B7 算出的 RES*

示例 res_star 取自 srsRAN 的 RES* 单元测试（test_security_kdf.cc），只用来说明格式。

成功：200

{ "ok": true }

失败

HTTPreason什么时候对应步骤
409no_pending没有先调用 /start，或者这个 challenge 已经用过了（包括失败过一次）C1
410expired/start 之后超过 30 秒C2
401res_mismatchRES* 不对：Client 的 K 不对，或者是冒充者C4
400bad_request缺字段，或者 res_star 不是 32 个 hex 字符—
{ "ok": false, "reason": "res_mismatch" }

副作用

  • 只要找到了 pending，不管成功还是失败都会删掉它（C3）。所以同一个 challenge 只能提交一次。

Client 本地结果（不经过网络）

这两种情况下 Client 直接停止，不发送 /finish。

结果步骤含义处理
mac_failB4AUTN 里的 MAC 不对，对方不知道 K，可能是假 Verifier拒绝，提示用户
sqn_failB5SQN 不比见过的大：重放，或者双方 SQN 乱了拒绝；如果确认是不同步，就手动重置 Verifier 里的 SQN

所有结果一览

结果谁判定HTTP谁被认证失败了
okVerifier200双方都通过
mac_failClient—Verifier
sqn_failClient—这个 challenge（旧的或者不同步）
res_mismatchVerifier401Client
no_pendingVerifier409请求顺序不对 / 重复提交
expiredVerifier410超时
