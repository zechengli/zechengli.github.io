General Flow：两个来回，双向认证

只有两个角色：Client（相当于 UE + USIM）和 Verifier（相当于 UDM + AUSF + AMF 合在一起）。 两个来回：① 拿 challenge，② 交 response。

Client 在 B4 认证 Verifier，Verifier 在 C4 认证 Client。

0. 事先配好的东西

谁字段长度说明
ClientSUPI字符串比如 imsi-001010123456789
K16 字节长期密钥
OPc16 字节运营商参数
SQN_max6 字节见过的最大 SQN，初始为 0
Verifier
每个 SUPI 一条		K, OPc各 16 字节和 Client 相同
SQN6 字节初始为 0
pending可为空未完成的认证：XRES*（16 字节）+ 过期时间
双方SVC / AMFSVC = "liteaka:demo"（代替 SN name），AMF = 0x8000（separation bit = 1）

1. 整体流程

Client                                          Verifier
  │                                                 │
  │  ① POST /start {supi}                           │
  │────────────────────────────────────────────────►│
  │                                                 │ A1. 查 supi
  │                                                 │ A2. SQN = SQN + 1
  │                                                 │ A3. 生成 16 字节随机 RAND
  │                                                 │ A4. MAC = f1(K, RAND, SQN, AMF)
  │                                                 │ A5. RES, CK, IK, AK = f2345(K, RAND)
  │                                                 │ A6. AUTN = (SQN⊕AK) ‖ AMF ‖ MAC
  │                                                 │ A7. XRES* = KDF(CK‖IK, SVC, RAND, RES)
  │                                                 │ A8. pending = {XRES*, 现在 + 30s}
  │               {rand, autn}                      │
  │◄────────────────────────────────────────────────│
  │                                                 │
  │ B1. RES, CK, IK, AK = f2345(K, RAND)            │
  │ B2. SQN = AUTN[0..5] ⊕ AK                       │
  │ B3. XMAC = f1(K, RAND, SQN, AMF)                │
  │ B4. XMAC ≠ MAC  → 停止：服务器是假的    ◄── 认证 Verifier
  │ B5. SQN ≤ SQN_max → 停止：重放 / 不同步          │
  │ B6. SQN_max = SQN                               │
  │ B7. RES* = KDF(CK‖IK, SVC, RAND, RES)           │
  │                                                 │
  │  ② POST /finish {supi, res_star}                │
  │────────────────────────────────────────────────►│
  │                                                 │ C1. 没有 pending → 失败
  │                                                 │ C2. 已过期 → 删掉，失败
  │                                                 │ C3. 删掉 pending（只能用一次）
  │                                                 │ C4. RES* ≠ XRES* → 失败   ◄── 认证 Client
  │                                                 │ C5. 成功
  │               {ok: true}                        │
  │◄────────────────────────────────────────────────│

2. 每一步在做什么

Verifier 出题（A1–A8）

步做什么为什么
A2SQN 先加 1即使这次认证失败，这个 SQN 也作废，和 5G 一样
A3随机 RAND每次 challenge 都不同，K 不会出现在空口上
A4MAC = f1(...)让 Client 能验证"出题的人有 K"
A5一次 f2345 得到 RES、CK、IK、AKCK、IK 只用来算 RES*，不再往下派生
A6AUTN 里的 SQN 用 AK 盖住防止旁听者通过 SQN 跟踪用户
A7XRES*：KDF 输出的低 128 位TS 33.501 Annex A.4；SN name 换成 SVC
A8存 pending，30 秒过期同一个 SUPI 再调用 /start 会覆盖旧的 pending

Client 验证并作答（B1–B7）

步做什么失败意味着什么
B4比较自己算的 XMAC 和 AUTN 里的 MACmac_fail：对方没有 K，是假 Verifier。不发送 ②
B5SQN 必须比见过的都大sqn_fail：收到的是旧 challenge（重放），或者双方 SQN 乱了。不发送 ②
B6更新 SQN_max必须在 B4、B5 都通过以后才更新
B7算 RES*

Verifier 判定（C1–C5）

步做什么失败返回
C1找 pendingno_pending
C2检查是否过期expired
C3先删 pending，再比较保证同一个 challenge 不能被试第二次
C4常数时间比较 RES* 和 XRES*res_mismatch

3. 和 5G AKA 原版的对应关系

LiteAKA5G AKA 里对应的
① POST /startAMF 向 AUSF/UDM 请求认证向量 + NAS Authentication Request（RAND, AUTN, ABBA, ngKSI）
A1–A7UDM 生成 5G HE AV；AUSF 算 HXRES*（LiteAKA 省掉）
B1–B7USIM 验 AUTN，ME 算 RES*
② POST /finishNAS Authentication Response（RES*）
C4SEAF 比 HXRES*，AUSF 比 XRES*（LiteAKA 合成一次比较）
B5 失败时5G 里 UE 发 Authentication Failure（Synch failure + AUTS）去重同步；LiteAKA 只在本地报错
成功以后5G 里接着派生 KAUSF → KSEAF → KAMF，发 Security Mode Command；LiteAKA 到此结束
