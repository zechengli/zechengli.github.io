LiteAAA on a B210

Status: it works. Run on 12 November 2026.

What we have: a SIM card, a phone, a B210 and a PC. No Open5GS and no core network.

Design

Where the code runs

WhereWhat runs thereThe key K
PCthe LiteAAA network half and the key storea copy, registered by hand
B210sends and receives every message as a Bluetooth packetnone
Phone appthe LiteAAA device halfnone
SIM cardchecks the network and makes the answerits own copy, never shown

Code structure

Two sides. The PC is Python; the phone app is Kotlin. The B210 is driven by the PC. The SIM card runs the real card's own code, which we did not write.

Runs onFileLinesWhat it is
PCliteaaa.py198the core rules: page, challenge, check, nonce (network half) and the device logic
PCcrypto.py160AES and Milenage, the key store that holds the card's K and makes the challenge
PCb210/ble.py106turns a message into a Bluetooth packet and back into samples for the B210
PCb210/air.py188drives the B210: transmit the packets, listen for the phone, carry LiteAAA's messages
PCb210/run_air.py60the run: register the card's K, then page and verify over the air
PhoneMainActivity.kt240the device half: hear a page, answer, ask the SIM, send the reply
PhoneSimCard.kt89hands RAND and AUTN to the real SIM card and reads its answer

The challenge is 32 bytes and a Bluetooth packet holds fewer, so it goes in two packets. The B210 sends each message over and over for a few seconds, because the phone hears only some packets.
