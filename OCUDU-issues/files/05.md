Title: F1-U CU-UP: 256 contiguous SDU discards wrap block_size to 0 (discarded SDUs still sent by RLC)
Labels (suggested): bug, f1u

---

## Summary

`f1u_bearer_impl::discard_sdu()` (CU-UP) extends the last discard block with `block_size++` for each contiguous PDCP SN. `block_size` is a `uint8_t` (`include/ocudu/nru/nru_message.h:31`), and only the number of blocks is bounded, not their size:

```cpp
// lib/f1u/cu_up/f1u_bearer_impl.cpp:202-216
    if (last_block.pdcp_sn_start + last_block.block_size == pdcp_sn) {
      last_block.block_size++;                  // <- the 256th contiguous SN wraps 255 -> 0
    ...
      if (discard_blocks.full()) {              // <- only the block count is bounded
        flush_discard_blocks();
```

The DU F1-U forwards the `{pdcp_sn_start, 0}` block unchanged (`lib/f1u/du/f1u_bearer_impl.cpp:96-103`), and RLC rejects a zero-size block without discarding any of its SNs (`lib/rlc/rlc_tx_am_entity.cpp:115-122`). PDCP TX has already removed those COUNTs from its TX window (`lib/pdcp/pdcp_entity_tx.cpp:1383-1385`), so RLC keeps transmitting SDUs that PDCP considers discarded. Longer runs wrap to `n mod 256` instead.

## Trigger

1. An AM DRB with 256 or more unacknowledged DL PDUs.
2. The UE sends a PDCP status report whose FMC is 256 or more COUNTs ahead of TX_NEXT_ACK.
3. `handle_status_report()` (`pdcp_entity_tx.cpp:629-631`) calls `discard_pdu()` for every COUNT below FMC, which reaches `f1u_bearer_impl::discard_sdu()` directly (`lib/cu_up/adapters/pdcp_adapters.h:111-118`) in one contiguous burst before the blocks are flushed.

In practice: a status report after PDCP re-establishment or data recovery (e.g. handover) at high DL rates.

## Reproduced

On `dev` 8fe05a213f, Debug build. The test below asserts the correct behaviour and fails on current code:

## Impact

One bearer: the SDUs in the wrapped block are transmitted anyway, wasting air-interface capacity and delaying the data queued behind them; the DU logs a warning and counts a discard failure. No crash.

## Suggested fix

In `f1u_bearer_impl::discard_sdu()`, extend the last block only while `block_size` is below its maximum and otherwise start a new block; with this change the new test and the rest of `f1u_cu_up_bearer_test` pass.
