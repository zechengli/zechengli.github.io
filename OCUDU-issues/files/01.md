Title: CU-CP: RRC reestablishment during a pending PDU session setup/modify releases the reestablished UE
Labels (suggested): bug, cu-cp

---

## Summary

If a UE reestablishes while an AMF-initiated PDU Session Resource Setup (or Modify) is waiting for RRCReconfigurationComplete, the CU-CP sends a **UEContextReleaseRequest** to the AMF. The AMF's UEContextReleaseCommand then releases the UE that has just reestablished successfully.

`handle_ue_context_transfer()` cancels the old UE's RRC transactions before the NGAP context is moved to the new UE:

```cpp
// lib/cu_cp/cu_cp_impl.cpp:681
old_ue->get_rrc_ue()->get_rrc_ue_control_message_handler().cancel_all_transactions();
```

The PDU session routine treats the cancelled reconfiguration as a failure and requests a UE release:

```cpp
// lib/cu_cp/routines/pdu_session_resource_setup_routine.cpp:278-285
CORO_AWAIT_VALUE(rrc_reconfig_result, rrc_ue->handle_rrc_reconfiguration_request(rrc_reconfig_args));
if (!handle_rrc_reconfiguration_response(response_msg, setup_msg, rrc_reconfig_result, logger)) {
  ...
  ue_task_sched.schedule_async_task(cu_cp_notifier.handle_ue_context_release(...));   // <- UE release requested
```

The request is sent before the transfer task runs. `update_ue_index()` (`lib/ngap/ue_context/ngap_ue_context.h:193`) then moves the same NGAP context to the new UE, so the AMF's release command lands on the reestablished UE. The modify routine has the same failure branch (`pdu_session_resource_modification_routine.cpp:183-191`).

## Trigger

1. UE attached with one PDU session.
2. AMF sends PDUSessionResourceSetupRequest for a second PDU session; the CU-CP sends the RRCReconfiguration.
3. Before RRCReconfigurationComplete, the UE sends RRCReestablishmentRequest, and the reestablishment succeeds.

In practice: a UE hits RLF at the cell edge while a QoS flow or bearer (e.g. for a voice call) is being added.

## Impact

The UE recovers from RLF and is then fully released, losing all its PDU sessions, not only the one being set up. No crash or leak.

## Suggested fix

Let the PDU session routines tell a cancelled reconfiguration apart from a failed one (e.g. return `cancelled` instead of `false`), and skip `handle_ue_context_release()` in that case while still reporting the failed session to the AMF.
