Title: RLC RX: t-Reassembly=ms0 is accepted but aborts the DU on the first gap (never expires in Release)
Labels (suggested): bug, rlc

---

## Summary

`rlc_t_reassembly_from_int()` (`include/ocudu/rlc/rlc_config.h:107`) accepts 0 (ms0, a valid TS 38.331 value), and the DU config validator uses it for the UM and AM `t_reassembly` settings (`du_high_config_validator.cpp:116`, `:2208`, `:2269`). The RX entities, however, only give the timer a duration when it is non-zero, and later start it unconditionally:

```cpp
// lib/rlc/rlc_rx_um_entity.cpp:33-34 (AM: rlc_rx_am_entity.cpp:48)
if (cfg.t_reassembly > 0) {
  reassembly_timer.set(std::chrono::milliseconds(cfg.t_reassembly), [this]() { on_expired_reassembly_timer(); });
// lib/rlc/rlc_rx_um_entity.cpp:262 (also :501; AM: :318, :742)
reassembly_timer.run();   // <- duration is INVALID_DURATION when t_reassembly == 0
```

`unique_timer::run()` asserts `duration != INVALID_DURATION` (`lib/support/timers.cpp:236`). With asserts enabled (Debug, RelWithDebInfo) the first reassembly gap aborts the process. In the default Release build (`ASSERT_LEVEL=NONE`) the timer is marked running but never expires, so gaps are never declared lost (UM) and never NACKed via t-Reassembly (AM).

## Trigger

1. DU config with `t_reassembly: 0` for a UM or AM bearer (accepted by the validator).
2. On that bearer, SN 0 is received, SN 1 is lost, SN 2 is received.

In practice: an operator choosing ms0 for a low-latency UM DRB, plus any ordinary UL PDU loss.

## Reproduced

On `dev` 8fe05a213f, Debug build and Release build (default `ASSERT_LEVEL`). The tests below (UM and AM) assert the correct behaviour and fail on current code:

## Impact

With asserts enabled, one lost PDU on such a bearer takes down the whole DU process and all its UEs. In Release there is no crash, but t-Reassembly never works on that bearer.

## Suggested fix

When `cfg.t_reassembly == 0`, call `on_expired_reassembly_timer()` inline (after setting the trigger) instead of `reassembly_timer.run()`, at the four call sites. With that change the new tests and the rest of `rlc_um_test` and `rlc_rx_am_test` pass.
