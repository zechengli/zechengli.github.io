Title: RRC: reestablishment timeout after context transfer never releases the new UE (NGAP/E1/F1 kept)
Labels (suggested): bug, cu-cp

---

## Summary

The reestablishment procedure moves the old UE's NGAP, F1AP and E1AP contexts to the new UE before it sends RRCReestablishment (`lib/rrc/ue/procedures/rrc_reestablishment_procedure.cpp:76`). If RRCReestablishmentComplete never arrives, the timeout branch only logs, and the common tail removes only the old UE:

```cpp
// lib/rrc/ue/procedures/rrc_reestablishment_procedure.cpp:138-149
  } else {
    logger.log_warning("\"{}\" for old_ue={} failed. Cause: timed out after {}ms", ...);   // <- no release here
  }
  if (not is_context_retrieved()) {
    cu_cp_notifier.on_rrc_reestablishment_complete(old_ue_reest_context.ue_index);      // <- removes the old UE only
  }
```

The new UE stays in `rrc_state::idle` holding the transferred contexts. `handle_rrc_reestablishment_complete()` (`lib/cu_cp/cu_cp_impl.cpp:646-652`) only removes the old UE, and CU-UP inactivity notifications are ignored for UEs that are not connected (`cu_cp_impl.cpp:391-397`). The context-modification-failure branch just above (`rrc_reestablishment_procedure.cpp:127-133`) does release the new UE.

Normally the DU's RLF-based F1AP UEContextReleaseRequest cleans the new UE up (checked on HEAD); the problem is that the CU-CP has no cleanup of its own if that request never comes.

## Trigger

1. Attach a UE with a DRB and SRB2.
2. Send RRCReestablishmentRequest for it from a new C-RNTI. The CU-CP transfers the context and sends RRCReestablishment.
3. Never send RRCReestablishmentComplete, and let T311 + guard time expire (13000 ms in the test environment).

In practice: RRCReestablishment is lost or the UE reselects another cell at the cell edge, and the DU does not send a release request for the new UE.

## Impact

If the DU does not send a release request, the CU-CP keeps an idle UE with NGAP, E1 and F1 contexts and no timer to remove it, and the AMF still sees the UE as CM-CONNECTED through this gNB. No crash; other UEs are unaffected.

## Suggested fix

In the timeout branch, release the new UE the same way the context-modification-failure branch does (`on_ue_release_required()` with `context.ue_index`); with this change the new test and the existing reestablishment tests pass.
