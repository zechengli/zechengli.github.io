Title: CU-CP: failed source UE Context Modification in handover leaves the source UE unreleased (UE stuck)
Labels (suggested): bug, cu-cp

---

## Summary

For an intra-CU handover, `handover_reconfiguration_routine` sends the source DU a UE CONTEXT MODIFICATION REQUEST with the HO command and `Transmission Action Indicator = stop`. It arms the source UE's fallback release timer only when that procedure succeeds. On failure it returns early, and `intra_cu_handover_routine` releases only the target UE:

```cpp
// lib/cu_cp/routines/mobility/handover_reconfiguration_routine.cpp:78-89
  if (!ue_context_mod_response.success) {
    ...
    CORO_EARLY_RETURN(false);                                        // <- nothing armed for source_ue
  }
  ...
  initialize_handover_ue_release_timer(source_ue.get_ue_index());   // <- success path only
```

The source DU has, however, already applied the stop. The DU F1AP applies the Transmission Action Indicator without checking `du_response.result` (`lib/f1ap/du/procedures/f1ap_du_ue_context_modification_procedure.cpp:51-56`, unlike the RRC-container guard above it), `handle_activity_stop_request()` disables RLF detection for the rest of the UE's life (`lib/du/du_high/du_manager/du_ue/du_ue_controller_impl.cpp:289-295`), and `restart` is rejected as unsupported (`f1ap_du_ue_context_modification_procedure.cpp:252`). The DU-side part is code reading plus a separate DU unit test.

So the source UE is left with DRBs stopped, no RLF detection and no CU-CP release timer, and nothing ever removes it. The inter-CU source path already arms the timer before sending the same stop (`lib/cu_cp/cu_cp_impl.cpp:1324`).

## Trigger

1. The CU-CP starts an intra-CU handover for a UE.
2. The source DU answers the UE Context Modification with a failure (or the procedure times out at the CU-CP). The DU has still applied the Tx stop, and the UE never gets the HO command.
3. The CU-CP releases only the target UE.

In practice: a resource or configuration failure at the source DU during handover; uncommon, but permanent for that UE.

## Impact

The source UE context stays allocated in the DU and the CU-CP with its user plane stopped and no timer to release it. The UE keeps SRB connectivity but has no data service; no crash.

## Suggested fix

Before `CORO_EARLY_RETURN(false)`, call `initialize_handover_ue_release_timer(source_ue.get_ue_index())` as the success path does; with this change the regression test passes.
