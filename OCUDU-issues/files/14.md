Title: RLC AM TX: t-PollRetransmit expiry re-queues an SN whose RETX is still pending (early max-retx)
Labels (suggested): bug, rlc

---

## Summary

When t-PollRetransmit expires with a stalled window, `on_expired_poll_retransmit_timer()` queues a full-SDU RETX for `tx_next_ack` and increments its RETX_COUNT without checking whether a RETX for that SN is already in `retx_queue`:

```cpp
// lib/rlc/rlc_tx_am_entity.cpp:1204-1209
bool retx_enqueued   = retx_queue.try_push(retx);   // <- no retx_queue.has_sn(st.tx_next_ack) check
if (retx_enqueued) {
  ...
  increment_retx_count(st.tx_next_ack);             // <- counted again while the previous RETX is pending
```

The STATUS path avoids this: `handle_status_pdu()` first drains `retx_queue` and rewinds RETX_COUNT (`:791`) before rebuilding it. The timer path does not, so if a NACKed SDU was only partly retransmitted (small grant) when the timer expires, its remaining bytes are queued twice and RETX_COUNT goes up although the first retransmission has not finished. TS 38.322 5.3.2 only increments RETX_COUNT for an SDU that is "not pending for retransmission already".

## Trigger

1. AM bearer with a stalled TX window (the test uses `max_window=4` and sends 5 SDUs; none is ACKed).
2. STATUS PDU NACKs SN 0 → RETX scheduled, RETX_COUNT=0.
3. A small grant sends only the first half of that RETX (with poll, since the window is stalled).
4. t-PollRetransmit expires before the rest is sent.

In practice: a stalled window plus small or intermittent DL grants and a scheduling gap of at least t-PollRetransmit. The test uses `maxRetxThreshold=2` so the effect is visible in two timer cycles.

## Impact

Bytes of a pending RETX are sent twice, and each occurrence spends one extra RETX_COUNT, so the DU declares RLF (`max_rlc_retxs_reached`) earlier than configured. Affects one UE.

## Suggested fix

In `on_expired_poll_retransmit_timer()`, skip the push and `increment_retx_count()` when `retx_queue.has_sn(st.tx_next_ack)`. With that check the new test and the rest of `rlc_tx_am_test` pass.
