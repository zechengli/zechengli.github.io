Title: PDCP TX: stale crypto reordering timer drops retransmissions after AM re-establishment (DL loss)
Labels (suggested): bug, pdcp

---

## Summary

For AM DRBs, `reestablish()` calls `retransmit_all_pdus()`. That function rewinds `TX_TRANS_CRYPTO` to `TX_NEXT_ACK`, bumps `retransmit_id` and re-dispatches crypto for every pending COUNT (`pdcp_entity_tx.cpp:984-989`). It does not stop `crypto_reordering_timer` and does not reset `TX_REORD_CRYPTO`. The timer is running whenever crypto is pending after a delivery (`:445-447`), so under DL traffic it usually is. When it expires with its old deadline, `crypto_reordering_timeout()` skips every COUNT whose `pdu` is still empty, including retransmissions whose new crypto has not finished yet:

```cpp
// lib/pdcp/pdcp_entity_tx.cpp:1462-1464, crypto_reordering_timeout()
  while (st.tx_trans_crypto < st.tx_reord_crypto) {
    if (!tx_window.has_sn(st.tx_trans_crypto) || tx_window[st.tx_trans_crypto].pdu.empty()) {
      logger.log_debug("Dropping SDU. count={}", st.tx_trans_crypto);   // <- retransmission still in crypto
```

When that crypto finishes, the PDUs are stored in the window, but `TX_TRANS_CRYPTO` is already past them, so they are never sent.

## Trigger

1. AM DRB. COUNT 0 and 1 are submitted. COUNT 0 is sent, and COUNT 1 is still in crypto, so the 40 ms timer starts.
2. 39 ms later, `reestablish()` re-dispatches crypto for COUNT 0 and 1.
3. 1 ms later, the old timer expires before that crypto finishes. COUNT 0 and 1 are skipped and never retransmitted.

The test holds the crypto tasks back with the suite's manual crypto executor. In practice: PDCP re-establishment of an AM DRB (handover, RRC re-establishment) while DL traffic flows. The loss needs the retransmission crypto to take longer than what was left of the old timer.

## Impact

AM DRB DL SDUs that re-establishment should retransmit (TS 38.323 5.1.2) are silently never sent, with only a debug log. They stay in the window until the discardTimer removes them. One DRB, no crash.

## Suggested fix

In `retransmit_all_pdus()`, after the rewind, call `crypto_reordering_timer.stop()` and set `st.tx_reord_crypto = st.tx_trans_crypto`. `apply_reordering()` then re-arms the timer for the new round. With this change the test passes, and the existing PDCP tests still pass.
