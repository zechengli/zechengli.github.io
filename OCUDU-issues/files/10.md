Title: PDCP TX: TX_NEXT_ACK parked on a COUNT removed by a status report (DL stall in Release, assert abort)
Labels (suggested): bug, pdcp

---

## Summary

`stop_discard_timer()` checks `tx_window.has_sn(TX_NEXT_ACK)` only before its advance loop. The loop moves `TX_NEXT_ACK` to `highest_count + 1`, and the function then indexes that slot without checking it. If a PDCP status report has already discarded that COUNT, the slot does not exist:

```cpp
// lib/pdcp/pdcp_entity_tx.cpp:1336-1354, stop_discard_timer()
  while (st.tx_next_ack <= highest_count) { ... st.tx_next_ack++; }   // <- may stop on a discarded COUNT
  ...
    auto& window_elem = tx_window[st.tx_next_ack];                     // <- no has_sn() check
```

**In Release builds (the default build type, asserts compiled out) this does not crash. Instead it silently kills the DRB's downlink.** `TX_NEXT_ACK` stays on the missing COUNT, and every later `stop_discard_timer()` call and discard-timer expiry returns early. Nothing leaves the window, although RLC keeps confirming delivery. Once the window is full, every new DL SDU is dropped (`full_window`) until the bearer is released. With asserts (Debug, RelWithDebInfo), the `circular_map` assert aborts the CU-UP process.

## Trigger

1. AM DRB with a finite discardTimer. COUNT 0..3 are sent.
2. The UE sends a PDCP status report with FMC=1 and bitmap `0b10000000`. COUNT 0 and 2 are discarded, and `TX_NEXT_ACK` = 1.
3. RLC confirms delivery of COUNT 1. `TX_NEXT_ACK` moves to 2 and `tx_window[2]` is read.

In practice: today, only a UE sending an unsolicited status report can trigger this. OCUDU never configures `statusReportRequired`, but the RX entity forwards any status report it receives. Once status reports are supported, this becomes the normal order of events after PDCP re-establishment.

## Impact

In Release, the DL of the affected AM DRB stops permanently, with only error logs. Other bearers are not affected. In assert builds, the CU-UP aborts and all its UEs lose their bearers.

## Suggested fix

After the advance loop, skip COUNTs that are no longer in the window, as `discard_pdu()` already does (`:1387-1390`): `while (st.tx_next_ack < st.tx_next && !tx_window.has_sn(st.tx_next_ack)) st.tx_next_ack++;`. With this change both tests pass in Debug and Release, and the existing PDCP tests still pass.
