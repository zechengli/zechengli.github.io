Formal methods · Specula × srsRAN Project

TLA+ model checking the 5G L2/L3 stack

Specula was pointed at the srsRAN Project gNB — the RLC AM, PDCP and RRC protocol machinery that every 5G attachment runs through — and asked to turn its UE-side L2/L3 behavior into TLA+ and machine-check it with TLC. The code implements the network side of the symmetric peer protocols (3GPP TS 38.322 / 38.323 / 38.331), so the gNB entities run the same state machines a UE does. This page follows the full Specula pipeline: source audit, modeling brief, TLA+ spec generation, and TLC verification of the interleavings no test suite reaches.

The pipeline

Specula is itself an agentic system: a code-analysis phase reads the target and its history and writes a modeling brief; a spec-generation phase turns the brief into TLA+; a verification phase runs TLC over bounded configs of the model, looking for invariant violations the C++ tests never provoke. The phases and what each produced:

What the audit found first: the architecture is not what the spec says

Phase 1 spent 1h21m of max-effort reasoning and ~37M tokens reading the stack (3,200 commit subjects enumerated, 14 bug-fix patches deep-read, 11 issue threads followed to the end). Before any model was written, four load-bearing facts surfaced that any faithful model must encode — each one a place where srsRAN deliberately departs from a naive reading of 3GPP:

Discovery 1 — RLC AM delivers out of order, on purpose An SDU is delivered to PDCP the moment it is fully received; RX_Next never skips an unfilled hole. Unit tests assert reverse-order upper delivery. The in-sequence guarantee lives one layer up, entirely in PDCP reordering.
Discovery 2 — SRBs configure t-Reordering = infinity Signaling radio bearers block forever on a missing PDCP count. No timer recovers an SRB hole; liveness rests wholly on RLC AM retransmission and, in the end, the max-retx→RLF escalation chain.
Discovery 3 — PDCP data recovery is discardTimer-gated The SDU copy kept for re-establishment retransmission is taken only when a discardTimer is configured — an optional DRB parameter. Bearers without it lose all in-flight un-ACKed data silently across a rebuild. A genuine spec deviation with silent-loss consequence.
Discovery 4 — a proven concurrency race already lives here Commit e3ac5a630 (2023-03) fixed a TSAN-caught race on the t-StatusProhibit running-flag. The lock-free triple-buffer STATUS exchange between RX (ue executor) and TX (pcell executor) is exactly the seam formal checking should stress.

The scenarios that went into the model

The modeling brief distills the audit into six scenarios; five are high-priority model targets, each anchored to a 3GPP question and to concrete commit/issue evidence:

ScenarioMechanism under the microscopeQPriority
1 · Max-RETX accounting & escalation RETX_COUNT +1/−1 sweeps, threshold checked on exact equality, a stop-everything latch set only at retx completion, and a once-latch adapter that is only reset when its dispatch fails. The chain every permanent in-order hole funnels into. Q2high
2 · RX reordering & STATUS under timer races t-Reassembly stop/start vs deferred expiry callbacks; t-StatusProhibit consolidation; the cross-executor triple-buffer; a defer-failure path that latches the running flag even when the defer fails — permanently disabling STATUS on that bearer. Q1/Q5high
3 · Internal loss between RLC and PDCP Crypto/UE executor queue-full drops and the TX crypto-reorder hole-skip: PDUs the peer already ACKed vanish inside the node. On an SRB (t-Reordering=∞) nothing ever recovers — no timer, no procedure, no terminal state. Q1high
4 · Rebuild, re-establishment & discard coupling Bearer rebuild drops RLC buffers; PDCP compensation is the discardTimer-gated data recovery; the retransmit_id epoch guard defends against stale-SN delivery. Q4high
5 · RRC procedure lifecycle & transactions 4-slot, 2-bit-TID transaction manager; completions routed by TID with no message-type check; TIDs reused round-robin; RLF release timer (t310+t311) sized to admit re-establishment — three open upstream crash reports (#1395/#1307/#1347) sit in this family. Q3high
6 · UM RX spec deviations (reference) Raw non-modular SN comparisons where the AM sister code is modular; bounded, self-correcting, recorded to justify leaving UM out of the model. —low

Invariants the model must uphold

InvariantTypeClaim
PdcpExactlyOncesafetyNo PDCP COUNT is delivered upward more than once — across delivery, expiry, rebuild, re-establishment.
PdcpInOrdersafetySDUs release upward in ascending COUNT order when out-of-order delivery is disabled.
NoSilentLosssafetyEvery accepted SDU ends in exactly one of: delivered, discarded-with-notification, timer-declared-lost, or covered by an RLF→release terminal path.
MaxRetxFinalitysafetyOnce an SN hits maxRetxThreshold, no further PDU for that bearer is transmitted and the RLF state moves off idle.
RlfTerminalitylivenessA RLF-detected UE always reaches a terminal state — never a silent standstill with no timer and no procedure.
SrbNoStucklivenessSRB delivery either progresses or the UE reaches terminal release.
StatusLivenesslivenessA persistent RX hole is reported in some transmitted STATUS PDU before it leaves the window.
TransactionSoundnesssafetyA procedure succeeds only on a completion of its own kind and epoch; stale completions never complete a reused TID.
TxWindowConsistencysafetyTX-window ACK/discard touches only SNs inside [tx_next_ack, tx_next); the retx queue never references absent slots.

Suspects queued for the checker

Seven model-checkable hypotheses (MC1–MC7) came out of the audit, each an unaudited interleaving the C++ unit tests don't reach — for example:

MC2 · the silently dead bearer Can the max-retx indication be consumed by a failed adapter dispatch (latch reset) while the peer stops requesting STATUS — leaving max_retx_reached set, no pulls, no RLF raised, no timer running? A bearer that dies without anyone noticing.
MC3 · the hidden hole Under t-Reassembly expiry racing window advance, multiple prohibited STATUS triggers and report truncation — can a persistently missing SN stay inside the RX window yet never appear in any transmitted STATUS PDU? The NACK that never leaves the building.
MC5 · the unrecoverable SRB hole A budgeted internal drop creates a PDCP hole on an SRB with t-Reordering=∞: no timer recovers it, and no RLF is ever reached. The starkest composition: the data-plane twin of Q3.

The full set, with test-verifiable (TV1–TV6) and code-review (CR1–CR6) companions, lives in the modeling brief. Six TV items are directly unit-testable — including TV1 (the STATUS disable on defer failure) and TV5 (silent end-to-end SDU loss at re-establishment without discardTimer).
