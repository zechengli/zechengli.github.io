RLC Acknowledged Mode (TS 38.322), RRC radio link failure (TS 38.331 §5.3.10 + §5.3.7), and RRC handover (TS 38.331 §5.3.5) — read out of the specification prose, translated into UPPAAL timed automata, and checked: 54 queries, 54 passes, 0 failures.

What UPPAAL is. UPPAAL is a model checker for timed automata — finite state machines whose transitions carry guards and assignments over real-valued clocks (t == T310, t311 = 0), and whose locations carry invariants (t310 <= T310). It explores not just the states of the machine but the zones of clock valuations reachable in each state, so it can answer questions a plain FSM checker cannot: can the handover race between “random access succeeds” and “T304 expires” end in both outcomes at once? — does every declared radio link failure eventually resolve into re-establishment or idle? 3GPP RRC and RLC behaviour is dominated by exactly this kind of counting (N310 out-of-syncs) plus hard timers (T310, T311, T301, T304, t-PollRetransmit, t-Reassembly, t-StatusProhibit), which makes the mapping natural: every timer becomes a clock with a guard-on-expiry edge, every counter becomes an integer, every indication between layers becomes a rendezvous channel.

1 · RLC Acknowledged Mode — TS 38.322

The AM entity is 3GPP's ARQ workhorse: the transmitter polls, retransmits on NACK or t-PollRetransmit expiry, and gives up after maxRetxThreshold retransmissions; the receiver reorders, detects gaps with t-Reassembly, and reports STATUS under t-StatusProhibit. The model is the uplink AM entity of a UE: three SDUs buffered at t=0, a send window of 2, pollPDU = 1 (every AMD PDU carries a poll), and a nondeterministic air interface that may lose each AMD PDU or STATUS PDU within finite budgets. Four processes: Tx (transmitting side), Rx (reception buffer + in-order delivery), RxStatus (STATUS construction under t-StatusProhibit), and Air (the lossy channel).

Two real bugs the checker caught in the first draft

Bug 1 — retransmitting a PDU that was never sent. The safety query A[] rx_next <= tx_next (“the receiver never advances past what was transmitted”) failed with a witness in which the receiver had delivered SN 1 although the transmitter had only ever sent SN 0. Cause: the t-PollRetransmit-expiry edge retransmitted sn_send = tx_ack even when tx_ack == tx_next — i.e. it “re”-transmitted a sequence number that had never been transmitted. Fixed by guarding the edge with tx_ack < tx_next (retransmit only what is actually outstanding).

Bug 2 — an infinite retransmission loop, invisible until the zone engine was fixed. The liveness query A<> Tx.T_Done or Tx.T_RLF failed with a genuine counterexample cycle: with the STATUS-loss budget exhausted, the transmitter retransmitted the same PDU on every poll expiry forever, and the receiver never had to answer. The spec says every retransmission — poll-driven or NACK-driven — increments RETX_COUNT, and at maxRetxThreshold the entity must indicate to upper layers instead of retransmitting again (clause 5.3.2, quoted above). The first draft only counted NACK-driven retransmissions; the fixed model counts both and reaches T_RLF either way. Both bugs were surfaced only after correcting a soundness flaw in the zone extrapolation (the checker's first k-normalisation cut reachable time — see the raw results).

2 · RRC radio link failure — TS 38.331 §5.3.10 + §5.3.7

RLF is a pure timer-and-counter machine. Layer 1 streams out-of-sync and in-sync indications; RRC counts. N310 consecutive out-of-syncs start T310; N311 consecutive in-syncs stop it; T310 expiry — or a random-access problem, or the RLC max-retransmission indication — declares the link failed. Then the UE stores a failure report, starts T311, hunts for a suitable cell; finding one starts T301 and sends RRCReestablishmentRequest; the network answers with RRCReestablishment (reconnected) or the timers expire (RRC_IDLE).

The model keeps the whole chain in one UE automaton with clocks t310, t311, t301 and counters n310, n311, plus an adversarial L1 process (out/in-sync indications on finite budgets — with N310=2, OOS budget 6 and IS budget 4, even a fully adversarial L1 cannot avoid two consecutive out-of-syncs forever: four in-syncs can split six out-of-syncs into at most five streaks) and a Net process (cell found / request accepted / request rejected).

The four leads-to queries are the point of using a timed model checker. UE.P --> (rec310 == 1 or rlf_report == 1) reads: from every state where T310 is running, the episode cannot avoid ending — the adversarial L1 may interleave indications however it likes, but the clock guard t310 == T310 plus the invariant t310 <= T310 force progress. A tester would need to enumerate schedules to gain this confidence; the zone-based reachability check gets it in one query.

3 · RRC handover (reconfiguration with sync) — TS 38.331 §5.3.5

A handover is a reconfiguration message carrying reconfigurationWithSync: the UE stops T310, starts T304, and random-accesses the target cell. If the target answers within T304 the UE is connected on the new cell; if T304 expires, the UE reverts to the source configuration, stores the failure, and runs the same re-establishment chain as after RLF — with reestablishmentCause = handoverFailure. The model keeps the not-activated-security branch of the spec as a guarded (disabled) edge, exactly as §5.3.5.5.2 defines it.

4 · Composition: RLC max-retx escalating into RRC — 38.322 §5.3.2 meets 38.331 §5.3.10.3

The two specifications are usually read separately, but they interlock through one sentence each. TS 38.322 says the AM entity, on hitting maxRetxThreshold, “indicates to upper layers that max retransmission has been reached”. TS 38.331 says RLF is declared “upon indication from MCG RLC that the maximum number of retransmissions has been reached”. The capstone model wires that indication to a rendezvous channel rlc_maxretx: a one-SDU AM entity fights the lossy air, and if its retransmission budget runs out, RRC hears it, declares RLF, stores VarRLF-Report, and runs the T311/T301 chain to re-establishment or idle.

Modeling conventions

Timer outcome = guard t == T + invariant t <= T on a dedicated location, so queries stay clock-free and liveness is exact. Rendezvous chan for layer indications; committed locations for zero-time actions (store report, start next timer); finite nondeterministic budgets for the environment (lossy air, adversarial L1, network answers) so liveness queries are meaningful.

Abstractions, stated plainly. Each model shrinks the data plane so the timer logic is exactly checkable: 3 SDUs with a send window of 2 (RLC), pollPDU = 1, STATUS abstracted to (ACK up to rx_next, NACK hole), byte-segment segmentation and HARQ invisible, DAPS bearers not modelled, AS security assumed activated for RLF re-establishment (the not-activated branch is kept as a disabled guarded edge in the handover model), no T316/T312, and physical-layer indications as atomic rendezvous events with finite budgets. Constants are shrunk (T310=4, T311=5, T301=3, T304=4, maxRetx=2, N310=2, N311=2) — the automaton structure, not the values, is what the specs fix; every value is a named constant at the top of each model, so changing them is a one-line edit.
